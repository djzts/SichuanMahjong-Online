# 设计文档

## 总体架构

```
            ┌──────────── 房主浏览器 ────────────┐
 房主 UI ──▶│ RoomController ── 规则引擎（纯函数） │
            │   │  计时 / 电脑出牌 / 托管          │
            │   └─ viewFor(room, 接收者) ──┐       │
            │                PeerHost ◀────┘       │
            └───────────────────┬──────────────────┘
                     WebRTC 数据通道（PeerJS）
         ┌───────────┬──────────┼──────────┬───────────┐
       玩家 2      玩家 3     玩家 4     观战 1      观战 2
   （只发操作意图，收自己的视图）     （只收牌河视图）
```

- **房主权威**：只有房主浏览器里有完整的牌局状态。其他客户端只发「操作意图」（出牌、碰、杠、胡、过、换三张、定缺），房主校验后推进状态，再给每个人发各自的视图。
- **单机模式**和联机房主用同一套 `RoomController`，只是不开 PeerJS。房主自己的操作也走 `intent → 校验 → 广播`，不走网络。
- **视图是唯一出口**：发给任何客户端的数据都由 `viewFor(room, viewer)` 生成。电脑 AI 也只读自己的视图，看不到别人的牌。

## 一局的状态机（`src/engine/game.ts`）

```
exchange（换三张）──全部选好──▶ void（定缺）──全部选好──▶ act(庄家)
act(座位, drew, afterKong)
  ├─ 出牌 ──▶ claim（有人能胡/碰/杠） 或 下家摸牌 ──▶ act
  ├─ 自摸 ──▶ 结算 ──▶ 下家摸牌 / ended
  ├─ 暗杠 ──▶ 收杠钱，牌尾补牌 ──▶ act(afterKong)
  └─ 补杠 ──▶ rob（有人能抢杠胡） 或 收杠钱，补牌 ──▶ act(afterKong)
claim：收齐所有有权响应的人的选择后统一裁决（胡 > 杠/碰）
  ├─ 胡（可一炮多响）──▶ 结算（含呼叫转移）──▶ 最后一个胡家的下家摸牌 / ended
  ├─ 杠 ──▶ 收杠钱，补牌 ──▶ act(afterKong)
  ├─ 碰 ──▶ act(drew=false，只能出牌)
  └─ 全过 ──▶ 出牌者的下家摸牌
rob：都选完后，有人胡则抢杠成功（补杠作废），否则补杠成立
摸牌时牌墙为空 ──▶ ended(wall-exhausted)：查花猪、查大叫、退税
只剩一个人没胡 ──▶ ended(three-won)
```

| 阶段     | 允许的操作                       | 超时处理（默认时长）                    |
| -------- | -------------------------------- | --------------------------------------- |
| exchange | 每人选 3 张同花色                | 自动选推荐的 3 张（20 秒）              |
| void     | 每人选一门缺                     | 自动缺张数最少的一门（20 秒）           |
| act      | 出牌；摸牌后可以自摸、暗杠、补杠 | 打刚摸到的牌，有缺门牌先打缺门（20 秒） |
| claim    | 胡 / 杠 / 碰 / 过                | 自动过（10 秒）                         |
| rob      | 抢杠胡 / 过                      | 自动过（10 秒）                         |

计时按「步骤」计算：同一步骤里别人先回应了，倒计时不会重置。电脑座位和断线的玩家由 AI 在 0.5–1.5 秒后操作。

`applyAction(state, seat, action)` 是纯函数：输入不会被修改，非法操作返回错误。洗牌用状态里保存的种子 PRNG，一局可以用「种子 + 操作日志（`state.log`）」完整重放。

## 房间、号位与轮换（`src/engine/room.ts`）

- **member（号位）**：本场的 4–7 位玩家，有累计积分。号位 1 永远是房主。
- **table**：本局上桌的 4 个人，`table[座位] = 号位`。规则引擎只认识 4 个座位。
- **bench（临时观察者）**：本局轮空的号位，下局一定上场。
- **spectator（观战者）**：只看不打、没有积分，不参与轮换，最多 2 人。

一局结束时 `computeRotation()` 算出下局的 `table` 和 `bench`（存在 `nextRotation` 里，结算窗口展示），下一局开始时生效。随机补位用这局的随机数状态，所以同一个种子结果可复现。具体规则和歧义处理见 README「5 / 6 / 7 人局」和「规则假设」第 22–28 条。

积分榜：每个号位的实时分数 = 之前各局的累计 + 本局到目前为止的结算（刮风下雨、每次胡牌都会立即计入）。

## 网络协议（`src/net/protocol.ts`，版本 `PROTOCOL_VERSION = 2`）

客户端 → 房主：

| 消息                                      | 说明                                                   |
| ----------------------------------------- | ------------------------------------------------------ |
| `{ t: 'hello', v, playerId, name, role }` | 握手。`role` 是 `player`（入座）或 `spectator`（观战） |
| `{ t: 'intent', action }`                 | 游戏操作                                               |
| `{ t: 'switch', role }`                   | 等待室里在座位和观战位之间切换                         |
| `{ t: 'ping' }`                           | 心跳回应                                               |

房主 → 客户端：

| 消息                                 | 说明                                                     |
| ------------------------------------ | -------------------------------------------------------- |
| `{ t: 'welcome', role, seat, note }` | 握手成功；`note: 'seats-full'` 表示座位满了，改为观战    |
| `{ t: 'state', view }`               | 完整视图快照（每次状态变化都发，重连时也发）             |
| `{ t: 'reject', reason }`            | `full` 房间已满 / `version` 版本不一致 / `kicked` 被移出 |
| `{ t: 'error', message }`            | 非法操作                                                 |
| `{ t: 'ping' }`                      | 心跳（每 4 秒）                                          |

握手流程：客户端连上房主的 Peer ID `scmj-<房间号>` → 发 `hello` → 版本不一致则 `reject(version)` → 房主按 `playerId` 找回原座位，否则分配空座位/观战位 → `welcome` + `state`。

断线检测：房主 13 秒没收到某个客户端的消息就认为它断线（该玩家由 AI 托管）；客户端 13 秒没收到房主的消息就认为房主断线，显示「游戏暂停」并持续重连。

## 谁能看到什么（`src/engine/view.ts`）

| 数据                                               | 自己 | 其他玩家           | 观战者、临时观察者（默认）   |
| -------------------------------------------------- | ---- | ------------------ | ---------------------------- |
| 自己的手牌、刚摸的牌                               | ✓    | ✗                  | ✗                            |
| 换三张选的牌                                       | ✓    | ✗                  | ✗                            |
| 牌河                                               | ✓    | ✓                  | ✓                            |
| 副露（碰、明杠、补杠）                             | ✓    | ✓                  | 开关 `visible.melds`         |
| 暗杠的牌                                           | ✓    | 背面（胡牌后亮出） | 开关 `visible.melds`（背面） |
| 手牌张数                                           | ✓    | ✓                  | 开关 `visible.handCount`     |
| 定缺                                               | ✓    | 全部选完后公布     | 开关 `visible.voidSuit`      |
| 胡牌者的手牌                                       | ✓    | ✓                  | ✗（硬性规定）                |
| 本局结束时所有人的手牌                             | ✓    | ✓                  | ✗（硬性规定）                |
| 结算的牌型、番型明细                               | ✓    | ✓                  | 开关 `visible.fanDetail`     |
| 每次结算的得失分、累计分、谁已胡、轮到谁、剩余张数 | ✓    | ✓                  | ✓                            |

观战者和临时观察者的视图里 `me` 为 `null`，也没有任何 `tile` / `hand` / `melds` / `revealed` 字段（`role` 分别是 `spectator` 和 `bench`）。`tests/view.test.ts` 在 AI 对局的每一步都检查这一点。房主会拒绝观战者和本局轮空的号位发来的任何游戏操作。

## 身份与断线重连

- 每个标签页第一次打开时生成 `playerId`（存在 sessionStorage），刷新后不变。
- 房主用 `playerId → 座位` 识别玩家；对局中，昵称相同、处于断线状态的座位也可以被接回（兜底：关掉标签页后重新打开）。
- 房主每次状态变化都把整个房间存到 localStorage（`scmj.host.<房间号>`）。房主刷新页面后用同一个 Peer ID 重新上线（如果 PeerJS 服务器还占着旧 ID，会每 3 秒重试），其他客户端自动重连。

## 测试

- `tests/hand.test.ts`：胡牌判定、七对、听牌、向听数。
- `tests/fan.test.ts`：所有番型、根、附加番、封顶、自摸加底/加番、查大叫最大番。
- `tests/game.test.ts`：换三张、定缺限制、自摸、点炮、一炮多响、过水不胡、碰杠优先级、明杠/暗杠/补杠、抢杠胡、杠上花、杠上炮 + 呼叫转移、血战中已胡不付钱、天胡地胡、海底、流局查花猪/查大叫/退税。
- `tests/view.test.ts`：观战者在每个阶段都收不到牌河以外的牌；玩家只看到自己的手牌；可见范围开关；观战位上限。
- `tests/controller.test.ts`：计时自动操作、电脑操作、断线托管、观战者和临时观察者不能操作。
- `tests/rotation.test.ts`：5/6/7 人局的下场与补位规则，包括流局、抢杠、两条规则落在同一人身上的情况。
- `tests/selfplay.test.ts`：4 个 AI 用固定种子自动打 1000 局，检查不报错、每局零和、任何时刻都是 108 张牌；5/6/7 人局各打 150 局，检查每局都是 4 人上桌、上局轮空的人这局都上场、积分零和。
